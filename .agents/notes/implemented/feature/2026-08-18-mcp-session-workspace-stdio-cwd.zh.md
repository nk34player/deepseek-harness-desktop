# Agent Note: mcp-client spawns stdio servers in the session workspace

Status: implemented

[English](2026-08-18-mcp-session-workspace-stdio-cwd.md) | 中文

## 问题

`mcp-client` 在插件加载时以 `cwd: config.cwd` 启动 stdio 服务器的子进程，而 `cwd` 默认为 `''`——即 Host 进程的工作目录（应用启动目录）。文件索引类服务器（fff 是动因案例）在启动时从该进程 cwd 派生搜索根，并且不暴露任何按调用传入路径的参数，因此它们搜索的是应用启动目录，而不是用户当前打开的项目文件夹。修复必须控制 spawn 时的 cwd，而一次工具调用所属的工作区只能按会话得知（`session.header.cwd`，与系统提示中的 `{{cwd}}` 以及 LSP 的 `sessionCwd` 同源）。

## 决策

`mcp-client` 的 stdio 配置新增可选的 `useSessionWorkspace: boolean`（默认 `false`）。开启时，子进程会在当前打开的工作区——最近进入的、带 cwd 的存活非子代理会话的 cwd——中 spawn，在没有任何会话打开时回退到 `cwd`（或 Host 工作目录）。当被跟踪的工作区变化时，连接 supervisor 会对子进程重新定位：关闭当前世代（等待其关闭以避免子进程重叠）并以新的 cwd 启动新世代，走独立的路径，不计入失败退避与尝试预算。

新的 `SessionWorkspaceTracker`（位于 `mcp-client/src/session-workspace.ts`）观察 `ctx.sessions`（通过 `ctx.get` 获取的可选服务）以及全局的 `session/created` / `session/disposed` 事件。它在构造时从已存活的会话播种（这样会话中途的 HMR 重载仍能保持正确的 cwd），并按进入顺序跟踪新旧程度，忽略无 cwd 以及子代理来源的会话。重新定位在一条 promise 链上串行，并取消任何已布防的失败重试定时器，因此重新定位与重试绝不会产生重叠的子进程。相同 cwd 的变化是无操作。

刻意采用显式开关：重新定位会重启子进程。这对无状态索引器（如 fff）是正确的，但对长驻的 GUI 桥接服务（例如 StudioMCP）会造成干扰，因此后者保持关闭该特性。

## 备选方案

**把工作区按调用注入工具参数**——已拒绝。fff 在子进程启动时一次性解析基路径，且不接受路径参数，因此没有可传入的按调用变量；只有 spawn cwd 能引导它。

**默认对每个 stdio 服务器启用 `useSessionWorkspace`**——已拒绝。每次切换工作区都重启会杀死长驻的桥接进程并重新索引从未要求过该行为的、有状态的服务器；显式开关把该行为限制在需要它的地方。

**复用失败重连路径来处理工作区变化**——已拒绝。它会消耗尝试预算（一次工作区切换会被计为一次中断）并给有意的用户操作增加退避延迟；专门的重新定位路径立即重启且从不触碰预算。

**在 `cwd` 上使用字符串哨兵（例如 `cwd: '@session'`）**——已拒绝。专门的布尔值在 schema 中更显式，也避免用魔法值重载路径字段。

## 后果

- 文件索引类 stdio MCP 服务器（fff）现在搜索用户打开的项目文件夹，并在用户打开不同工作区时自动重新定位，无需在配置文件中硬编码路径。
- 被跟踪的值是「当前打开工作区」的服务器侧近似：最近进入的合格存活会话。在没有新建会话的情况下于不同工作区的两个已打开会话之间切换不会触发重新定位（浏览器的当前会话标签页不会上报给服务器）；主导流程——打开工作区与新建会话——都会创建会话并正确重新定位。若要做到精确，需要一条从浏览器到 Host 的「活跃会话」RPC，超出本次范围。
- 绑定工作区的服务器按设计在工作区切换时重新定位（重启）；不能重启的服务器保持不设置该开关。
- stdio 子进程的 cwd 通过 `createTransport(config, cwdOverride)` 传入，因此传输层仍是被解析后的 spawn cwd 的纯函数。
