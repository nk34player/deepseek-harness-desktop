# Agent Note: mcp-client spawns stdio servers in the session workspace

Status: implemented

[English](2026-08-18-mcp-session-workspace-stdio-cwd.md) | 中文

## 问题

`mcp-client` 以 `cwd: config.cwd` 启动 stdio 服务器的子进程，而 `cwd` 默认为 `''`——即 Host 进程的工作目录（应用启动目录）。文件索引类服务器（fff 是动因案例）在启动时从该进程 cwd 派生搜索根，并且不暴露任何按调用传入路径的参数，因此一个共享的子进程只能搜索固定的文件夹。当用户在不同工作区中打开多个会话／标签页时，子进程的文件夹必须匹配调用它的会话——但共享子进程做不到，在会话切换时迁移它又会让来自原始会话的调用搜索到错误的文件夹。

## 决策

`mcp-client` 的 stdio 配置新增可选的 `useSessionWorkspace: boolean`（默认 `false`）。开启时，插件为**每个存活会话运行一个受监督的子进程**，每个子进程都以该会话的工作区（`header.cwd`）为根目录，并将其工具**限定注册到该会话的 agent 作用域**（通过 `agent.ctx.tools.register`），因此不会产生工具名冲突，一个会话的模型只会看到它自己会话的工具。会话创建时（`agent/created`）启动其子进程，会话销毁时（`agent/disposed`）将其拆除；插件加载时对已存活的 agent 播种（HMR 安全）。无 cwd 以及子代理来源的会话会被跳过（子代理继承其父进程的 cwd）。

这是 Cursor 的 project-scope MCP 以及其他多工作区工具所用的按工作区实例化模型：每个工作区都有自己的服务器，因此绝不会出现错误工作区窗口、切换时重启或跨会话污染。此功能需要 `agents` 服务；缺少时服务器回退到配置的 `cwd`（记录日志）。

刻意采用显式开关：每个会话一个子进程对无状态索引器（如 fff）是正确的，但对长驻的 GUI 桥接服务（例如 StudioMCP）开销过大，因此后者保持关闭该特性。

## 备选方案

**把工作区按调用注入工具参数**——已拒绝。fff 在子进程启动时一次性解析基路径，且不接受路径参数，因此没有可传入的按调用变量；只有 spawn cwd 能引导它。

**一个共享子进程跟随当前查看的会话并在切换时重新定位**——已拒绝。单个共享服务器无法服务不同工作区的会话；重新定位会把子进程迁移到新查看会话的工作区，使来自其所属会话的调用搜索到错误文件夹。按会话启动子进程能让每个工作区的服务器保持稳定且正确。

**默认对每个 stdio 服务器启用 `useSessionWorkspace`**——已拒绝。每个会话一个子进程对长驻桥接服务开销过大；显式开关把该行为限制在需要它的地方。

**复用失败重连路径来处理工作区变化**——已拒绝。按会话模型下不存在工作区变化；每个按会话的子进程都独立拥有自己的重连预算。

**在 `cwd` 上使用字符串哨兵（例如 `cwd: '@session'`）**——已拒绝。专门的布尔值在 schema 中更显式，也避免用魔法值重载路径字段。

## 后果

- 文件索引类 stdio MCP 服务器（fff）现在搜索它们被使用的会话，以该会话的工作区为根目录，无需在配置文件中硬编码路径。
- 每个会话的工具都限定到该会话的 agent，因此不同工作区的两个会话绝不会看到或返回彼此的文件夹内容。
- 绑定工作区的服务器在会话切换时绝不会重新定位或重启；它随会话一起启动与拆除。
- stdio 子进程的 cwd 通过 `createTransport(config, cwdOverride)` 传入，因此传输层仍是被解析后的 spawn cwd 的纯函数。
