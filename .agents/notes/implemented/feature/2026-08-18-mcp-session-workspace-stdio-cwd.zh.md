# Agent Note: mcp-client spawns stdio servers in the session workspace

Status: implemented

[English](2026-08-18-mcp-session-workspace-stdio-cwd.md) | 中文

## 问题

`mcp-client` 在插件加载时以 `cwd: config.cwd` 启动 stdio 服务器的子进程，而 `cwd` 默认为 `''`——即 Host 进程的工作目录（应用启动目录）。文件索引类服务器（fff 是动因案例）在启动时从该进程 cwd 派生搜索根，并且不暴露任何按调用传入路径的参数，因此它们搜索的是应用启动目录，而不是用户当前打开的项目文件夹。修复必须控制 spawn 时的 cwd，而一次工具调用所属的工作区只能按会话得知（`session.header.cwd`，与系统提示中的 `{{cwd}}` 以及 LSP 的 `sessionCwd` 同源）。

## 决策

`mcp-client` 的 stdio 配置新增可选的 `useSessionWorkspace: boolean`（默认 `false`）。开启时，子进程会在当前打开的工作区——最近进入的、带 cwd 的存活非子代理会话的 cwd——中 spawn，在没有任何会话打开时回退到 `cwd`（或 Host 工作目录）。

子进程会**绑定到它观察到的第一个工作区，并一直留在那里**。一个共享的服务器无法服务多个工作区的会话：在会话切换时迁移它，会让来自原始会话的调用搜索到错误文件夹。因此连接 supervisor 至多对子进程重新定位一次——定位到第一个工作区，关闭当前世代（等待其关闭以避免子进程重叠）并以该 cwd 启动新世代，不计入失败退避与尝试预算——之后忽略所有更晚的工作区变化。重连时也复用同一个已绑定的 cwd。

新的 `SessionWorkspaceTracker`（位于 `mcp-client/src/session-workspace.ts`）观察 `ctx.sessions`（通过 `ctx.get` 获取的可选服务）以及全局的 `session/created` / `session/disposed` 事件。它在构造时从已存活的会话播种（这样会话中途的 HMR 重载仍能保持正确的 cwd），并按进入顺序跟踪新旧程度，忽略无 cwd 以及子代理来源的会话。观察到的第一个工作区绑定子进程；之后的变化均为无操作。

浏览器通过 `session.activate` RPC 上报它当前正在查看的会话；网关解析该会话并发出非日志型 `session/activated` 宿主事件。跟踪器把被激活的会话当作新建会话一样处理，因此当前工作区始终反映被查看的标签页——但由于子进程已经绑定，激活并不会对它重新定位。

## 备选方案

**把工作区按调用注入工具参数**——已拒绝。fff 在子进程启动时一次性解析基路径，且不接受路径参数，因此没有可传入的按调用变量；只有 spawn cwd 能引导它。

**跟随活跃标签页并在每次会话切换时重新定位**——已拒绝。一个共享的服务器无法服务不同工作区的会话；重新定位会把服务器迁移到新查看会话的工作区，使来自其所属会话的调用搜索到错误文件夹。绑定到第一个工作区能让每个服务器的搜索根保持稳定。

**默认对每个 stdio 服务器启用 `useSessionWorkspace`**——已拒绝。每次切换工作区都重启会杀死长驻的桥接进程并重新索引从未要求过该行为的、有状态的服务器；显式开关把该行为限制在需要它的地方。

**复用失败重连路径来处理工作区变化**——已拒绝。它会消耗尝试预算（一次工作区切换会被计为一次中断）并给有意的用户操作增加退避延迟；专门的重新定位路径立即重启且从不触碰预算。

**在 `cwd` 上使用字符串哨兵（例如 `cwd: '@session'`）**——已拒绝。专门的布尔值在 schema 中更显式，也避免用魔法值重载路径字段。

## 后果

- 文件索引类 stdio MCP 服务器（fff）现在搜索用户打开的项目文件夹，绑定到它们观察到的第一个工作区，无需在配置文件中硬编码路径。
- 被跟踪的工作区仍然反映浏览器的活跃标签页（浏览器通过 `session.activate` 上报正在查看的会话，网关重新发出 `session/activated`），但子进程已经绑定，不会重新定位。活跃会话这一事实只是服务器侧内存（绝不持久化）；重连时会重新上报。
- 绑定工作区的服务器在更晚的会话切换时绝不会重启，因此不能重启的服务器也可以安全使用该开关。
- stdio 子进程的 cwd 通过 `createTransport(config, cwdOverride)` 传入，因此传输层仍是被解析后的 spawn cwd 的纯函数。
